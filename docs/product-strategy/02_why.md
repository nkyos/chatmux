# Why — なぜ chatmux が必要なのか

## 課題 (Problems)

### 1. セッションが散らばる
Claude Code はターミナルタブ、Cursor はエディタ内、Copilot は別のエディタ…
複数のエージェントセッションがバラバラの場所に存在し、全体像が見えない。

### 2. 「待ち」の管理ができない
エージェントにタスクを投げて返答を待つ間、別の作業をしたい。
しかし返答が来たことに気づく手段が限られている。
タブを巡回して確認するしかない。

### 3. 並行セッションの切り替えが重い
3つのタスクを3つのエージェントセッションで同時に進めている場合、
それぞれのコンテキスト（何を頼んだか、どこまで進んだか）を
頭の中で管理する必要がある。

### 4. エージェント横断の統一体験がない
各エージェントは独自のUI・操作体系を持つ。
「セッション一覧を見る」「通知を受け取る」という基本的な操作すら
ツールごとにバラバラ。

## 誰のためのツールか

- **複数のコーディングエージェントを日常的に使う開発者**
- **1つのエージェントでも複数セッションを並行して走らせる人**
- **エージェントの作業を「待つ」時間を効率的に使いたい人**

## Why Now

- コーディングエージェントが実用段階に入り、「1日1回使う」から「常時複数走らせる」フェーズに移行しつつある
- エージェントの自律性が上がり、「投げて待つ」ワークフローが増えている
- まだこの領域に特化したクライアントツールが存在しない
